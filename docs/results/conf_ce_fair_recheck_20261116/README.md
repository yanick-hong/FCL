# Conf+CE 与 FCL+CE 独立复查

本目录记录附加复查，不修改论文中的实验说明、设置或现有结果。

两组使用相同的原始CLIP缓存、训练/验证/测试划分、纠错人数、线性头和混合硬标签CE；仅纠错样本的选择规则不同。Conf选择最大类概率最低的样本，FCL使用冻结的原型纠错mask。

## 固定搜索协议

完整设置在`search_protocol.json`。两方法均使用学习率网格0.001/0.002/0.004、AdamW、权重衰减0.0001、batch1024、100epochs和Cosine调度；patience101保证完整训练100轮。

先以seed42在每个方法和数据集上按验证集最高准确率选学习率，并列取较小学习率；再用选定学习率训练seed43/44。共50个正式训练。所有候选、失败、验证历史和测试结果均保留，不按预设胜负数量筛选结果。

采用CPU执行，每个训练进程的torch/BLAS线程上限为2，最多3个数据集同时执行。该执行设置与历史GPU运行不同，明确作为独立复查记录。已有GPU核心/基线队列、源码、HEAD及配置保持不动。

## 解释边界

- `confidence-threshold`不是Conf+CE的有效调参项；它仅控制旧脚本里的FixMatch分支。
- 标签层初查中，同纠错人数的Conf标签质量在五集均高于原型。训练复查允许任何真实结果，不能承诺FCL在指定数量的数据集获胜。
- 恢复的Caltech为101类，原文报告102类。所有新复查均不能冒充原稿历史同协议运行。
- 三种子统计以固定划分、VLM标签、纠错mask和选定学习率为条件；seed42也用于验证集调参，不涵盖重新划分、重新标注或搜索协议变化的不确定性。
